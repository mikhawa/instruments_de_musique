## Dockerisation complète (demandée directement à l'agent devops par l'utilisateur)

L'utilisateur a demandé à l'agent `devops` (sonnet) « crée les images docker » puis « tout doit être dockerisé ». Ces fichiers avaient d'abord été pris à tort pour des ajouts hors demande et supprimés, puis recréés par l'agent.

- `Dockerfile` : PHP 8.4-FPM Alpine (intl, pdo_mysql, opcache, zip, composer), cibles `dev` et `prod`
- `.dockerignore`, `docker/nginx/default.conf`, `docker/php/entrypoint-dev.sh` (`composer install` si `vendor/` absent)
- `compose.yaml` : services `php`, `web` (Nginx, http://localhost:8080), `database` (MariaDB 11.4)
- `compose.override.yaml` : port base 3307, Mailpit, phpMyAdmin (http://localhost:8081)
- Commandes désormais : `docker compose exec php php bin/console ...`, `docker compose exec php php bin/phpunit`

## Point bloquant

`composer.lock` exige PHP ≥ 8.4 (doctrine/doctrine-bundle 3.3.4, doctrine/doctrine-migrations-bundle 4.0.1, doctrine/collections 3.1.0, symfony/stimulus-bundle 3.7.0, symfony/ux-turbo 3.7.0…) alors que la production Hostinger est prévue en PHP 8.3.

## Suite : nettoyage et phpMyAdmin

- Suppression temporaire des fichiers Docker (erreur d'appréciation de l'orchestrateur), recréés ensuite par `devops` ; `compose.app.yaml` a été fusionné dans `compose.yaml`.
- Ajout de phpMyAdmin (dev uniquement) par `devops` (sonnet) : service `phpmyadmin` (image `phpmyadmin:5.2`) dans `compose.override.yaml`, http://localhost:8081, connexion `app` / `!ChangeMe!` testée ; section « phpMyAdmin (dev) » dans `docs/devops/docker-setup.md`.
- Vérification par l'agent principal (opus) : `docker compose config -q` OK, HTTP 200 sur :8081.
